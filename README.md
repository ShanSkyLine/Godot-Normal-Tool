# Normal-Godot

**v0.8.0**

Веб-инструмент для генерации карт нормалей (normal maps) из 2D-спрайтов — заточен под динамическое освещение в Godot 4.x. Работает полностью в браузере, на чистом HTML/CSS/JS, без сборки и без сервера: ничего никуда не загружается, все вычисления идут локально на canvas.

🔗 **[Открыть онлайн](https://shanskyline.github.io/Godot-Normal-Tool/)** — либо просто открой `index.html` в браузере, оба варианта работают одинаково.

## Что нового в v0.8.0

Новый локальный движок **Surface** с четырьмя категориями:

- **Объём по силуэту** (по умолчанию): округлый рельеф по расстоянию до альфа-контура. Детали цвета по умолчанию выключены: чёрный глаз или краска не становятся углублением.
- **Рельеф текстуры**: яркость задаёт высоту; доступны сглаживание, сила деталей и «Тёмное = выпуклое».
- **Управляемая форма**: объём по силуэту и кисти выпуклости, впадины, плоскости, направлений влево/вправо/вверх/вниз. Радиус, сила, отмена целого мазка и просмотр normal map. Направление означает ориентацию поверхности, а не распознавание поворота персонажа.
- **Карта высот**: загрузка карты точного размера текущего кадра или слоя. Белое означает большую высоту; инверсия меняет знак. До загрузки карты результат плоский.

Выберите Surface в разделе генерации на компьютере или телефоне. Сила и Z Range управляют наклоном нормалей. Правки относятся к текущему кадру; в Layers сначала выберите отдельный слой (solo). Цвет, альфа и размер исходника сохраняются. Classic и X доступны для совместимости.

Это геометрическая эвристика, **не AI-распознавание** глаз, материалов или настоящей глубины. Реализм зависит от исходного силуэта и авторских правок. Автоматический силуэт не восстанавливает скрытую геометрию; непрозрачное прямоугольное изображение получает объём по рамке. Для таких изображений используйте текстуру, карту высот или ручную форму. Режим X Texture остаётся вариантом для бесшовных тайлов.

Настройки Surface сохраняются при переключении проектов и в шаблонах настроек. Ручные мазки и загруженные карты высот остаются с изображением во вкладке проекта **только в текущей сессии**; шаблон не сохраняет изображения или мазки. Редактор ограничен 4000 отпечатками на изображение, чтобы ограничить стоимость пересчёта.

Исправления: отмена устаревших запусков генерации, сохранение выбранного кадра при пересчёте, экспорт активной пользовательской/Fill-карты во всех PNG-экспортах и Godot-пакете, проверка размеров ячеек спрайтшита.

Проверки: `node tests/surface.test.js`, `node tests/generation.test.js`. Браузерные проверки: `node tests/browser.test.cjs` (требуется Playwright и Chromium).

## Что это

2D-спрайты обычно рисуются плоскими, поэтому `PointLight2D` в Godot их не освещает объёмно. Normal-Godot решает эту проблему: загружаешь спрайт — получаешь готовую карту нормалей, по которой движок Godot 4 честно считает освещение по каждому пикселю (рельеф, блики, тени от направления света).

Инструмент умеет:

- **Генерировать normal map** из спрайта двумя движками на выбор — Classic (Sobel/Scharr по яркости) и экспериментальный X (многомасштабный, без «ореола» по краям альфы, с пресетами Soft / Balanced / Crisp)
- Работать с **одиночным спрайтом**, **спрайтшитом** (автонарезка по сетке) или **набором кадров** анимации
- **Layers** — накладывать несколько изображений как отдельные слои со своим normal map у каждого, свободно двигать их друг относительно друга (drag или точный X/Y), смотреть слой отдельно или все вместе
- Строить **Ambient Occlusion** карту (SSAO-подобный алгоритм по альфа-каналу)
- Показывать **живой предпросмотр с освещением** — до 4 цветных источников света, перетаскиваемых на XY-площадке
- **Fill Normals** — быстро сгенерировать радиальную/направленную нормаль для круглых/бесформенных объектов без реальной генерации по текстуре
- Экспортировать: PNG карты нормалей (один кадр / спрайтшит / все кадры по отдельности / произвольный тайлшит), готовый **Godot ZIP-пакет** (все кадры + CanvasTexture + SpriteFrames + сцена + GDScript со светом + README), сниппет GDScript и `.import` конфиг отдельно
- Локализация **RU/EN** с автоопределением языка браузера

## Как это работает

1. **Загрузка** — спрайт читается в canvas, из него берётся `ImageData` (RGBA по пикселям).
2. **Генерация карты высот** — из RGB считается яркость (luma), опционально инвертируется и блюрится.
   - *Classic*: яркость домножается на альфу, затем оператором Собеля/Шарра считается градиент по X/Y → вектор нормали `(dx, dy, zRange)`, нормализуется и пишется в RGB как `(n*0.5+0.5)*255`.
   - *X (experimental)*: вместо домножения на альфу цвета «растекаются» (color bleeding) за пределы силуэта — это убирает ложный резкий градиент на краю прозрачности. Затем строится 2–3 октавы градиента (мелкая/средняя/крупная детализация), опционально добавляется купол по силуэту (объём тела) и финальное сглаживание + микро-контраст для восстановления резкости мелкой текстуры.
3. **Нормаль → цвет**: итоговый вектор `(nx, ny, nz)` кодируется как стандартная tangent-space normal map (R=X, G=Y, B=Z, альфа сохраняется от источника).
4. **Lit-превью**: карта нормалей освещается прямо в браузере простым Blinn-Phong (диффуз + спекуляр) по каждому источнику света из панели — это то же самое, что увидит движок Godot с `PointLight2D` и normal map на материале.
5. **AO-карта**: для каждого непрозрачного пикселя пускаются 12 лучей по кругу на заданный радиус; если луч быстро упирается в другой непрозрачный пиксель — точка считается более «затенённой».
6. **Layers**: каждый слой генерирует normal map независимо (с кэшем, чтобы перетаскивание не пересчитывало текстуру), затем все видимые слои альфа-компонуются в общий холст в порядке стека.
7. **Экспорт для Godot**: `Godot package` формирует один ZIP с парными PNG, относительными ссылками в `CanvasTexture`/`SpriteFrames`, готовой сценой и автоматически запускаемым скриптом света. Импорт PNG и кеширование выполняет сам Godot.

```

ui.js         — вкладки, мобильные шторки, тултипы, обучение, хоткеи
```

## Использование в Godot 4

1. Сгенерируйте карту нормалей и нажмите **Пакет для Godot**.
2. Скачивается один `normengine_godot_0.8.0.zip`: все кадры с парными diffuse/normal PNG, `CanvasTexture` для каждого, `SpriteFrames` для анимации, сцена `asset/demo.tscn`, свет и самостоятельный `project.godot`.
3. Для быстрой проверки распакуйте ZIP, откройте `project.godot` в Godot 4, дождитесь импорта и нажмите F5. Свет создаётся автоматически с радиальной текстурой и высотой.
4. Для существующего проекта копируйте **только папку `asset/`** в любую папку проекта. Относительные ссылки остаются рабочими. Откройте `demo.tscn` или назначьте `*_material.tres` в `Sprite2D.Texture`; для `AnimatedSprite2D` используйте `animation.tres` и анимацию `default`.
5. При использовании сцены в игре удалите её `Camera`, если у вас уже есть камера, и `Ambient`, если освещение Canvas уже настроено.

Godot сам создаёт `.png.import`, UID и кеш `.godot`. Экспорт не содержит выдуманных адресов кеша. Кнопка настроек импорта копирует инструкцию: lossless, normal map Enable, Invert Y Off. Нормали назначаются через **CanvasTexture**, а не CanvasItemMaterial.

Экспорт сохраняет все кадры, FPS и включённые источники света; активная custom/Fill-карта заменяет нормаль выбранного кадра. Цвет, энергия, положение и высота света переносятся приблизительно: браузер использует Blinn-Phong с направленным светом, а Godot — PointLight2D. Softness/highlight не воспроизводятся точно. Для отбрасываемых теней нужен LightOccluder2D в вашем проекте; геометрия теней автоматически не создаётся.

`node tests/godot.test.js` и `python3 tests/zip.test.py` проверяют архив, PNG, ссылки, кадры и анимацию. `python3 tests/godot-runtime.test.py /path/to/godot` проверяет реальный импорт и запуск в Godot, включая перенос в вложенную папку. Workflow содержит установку Godot 4.5.1 и браузерные проверки.
